# H5 移植指南（Tile2D）

> 本文是「跨平台移植指南」的 H5 子文档：**以项目里真实可运行的 `h5-demo/` 为例，一步步教你把 Tile2D 移植到浏览器（JavaScript）**。
> 渲染方式是 **DOM**——瓦片是真实元素（对照 app 端 `TileLayout` 用真实子 View 承载瓦片），不做 Canvas 自绘。
> 本文的代码块都是**从 `h5-demo/` 里摘出来的真实代码**；遇到「完整代码见某文件」时，以文件为准。

## 怎么用这份指南

- **前提**：先读「跨平台移植指南」里 `LayoutEngine` 那一章（`sync` 的 3a–3g、`seek`、`diff` 的职责），本文不再重复讲原理。
- **读法**：每一步都是「要移植什么 → 真实代码长什么样 → 自检点」。
- **顺序**：先引擎（纯算法），再容器层（DOM），最后交互与菜单——和实际写这份 demo 的顺序一致。
- **运行**：直接双击 `h5-demo/index.html`（本地 `file://` 即可，无任何网络依赖），或 `python3 -m http.server` 后访问。

## 第 0 步：先想清楚要复刻哪些东西

移植不是「把 Java 一行行抄成 JS」，而是**先分清哪部分必须逐行对齐、哪部分可以按需复刻**：

| Java 侧 | H5 侧 | 复刻程度 |
|---|---|---|
| `LayoutEngine` | `h5-demo/tile2d.js` | **逐行对齐**（含注释），行为必须完全一致 |
| `LayoutModel` | `h5-demo/tile2d.js` | 逐行对齐 |
| `TileLayout`（ViewGroup + 真实子 View） | `TileDomCore`（容器 + 真实 DOM 元素） | **按需复刻**：进出、摆放、缩放、回收、命中测试 |
| `TileManager`（预取/濒死区） | —— | 演示不需要，直接砍掉 |
| `DimenManager` | `TileDomCore` 里的尺寸表 | 按需：逐列宽 / 逐行高 + 默认值 |
| `TileCoreService`（调度层） | `main.js` + `TileDomCore` | 按需：只保留演示用到的部分 |
| 柏林噪声 + 24 色渐变 | `h5-demo/noise.js` | **逐位对齐**（同种子必须出同一张图） |

一句话：**引擎和随机数要「一模一样」，容器层与调度层「照着意图重写」。**

示例共 4 个文件：

- `h5-demo/index.html` — 页面结构与样式（手机优先、安全区适配）
- `h5-demo/tile2d.js` — `LayoutModel` + `LayoutEngine`（逐行对齐）+ `TileDomCore`（DOM 容器层）
- `h5-demo/noise.js` — `java.util.Random` 复刻 + 柏林噪声 + 24 色渐变
- `h5-demo/main.js` — 适配器 + DOM 瓦片渲染 + 手势（惯性滚动 / 捏合缩放）+ 菜单

> **单元测试不放进工程**：本项目要求测试代码只存在于**项目外的临时目录**（也方便对着 Java 版做同构差分）。`h5-demo/tile2d.js` 底部保留 `module.exports`，就是给外部测试脚本 `require` 用的。

## 第 2 步：布局模型（LayoutModel）

引擎要两个模型：`original` 记录真实状态，`output` 是给外部读的快照。对照 Java 的 `LayoutModel`：

```js
class LayoutModel {
    constructor() {
        this.colStart = 0; this.rowStart = 0;
        this.colEnd = -1; this.rowEnd = -1;      // 空区间：[0,-1]
        this.offsetX = 0; this.offsetY = 0;
        this.contentWidth = 0; this.contentHeight = 0;
    }
    copyTo(m) { /* 八个字段整体拷贝 */ }
    newInstance() { const m = new LayoutModel(); this.copyTo(m); return m; }
    reset() { /* 回到空区间 */ }
}
```

**自检点**：`colEnd = -1`、`rowEnd = -1` 表示「还没有任何内容」，引擎的合法性短路会用到这个约定。

## 第 3 步：布局引擎（LayoutEngine）——必须逐行对齐

引擎是整份移植里唯一「不能自己发挥」的部分。`h5-demo/tile2d.js` 里那 500 行就是 Java 版的同构翻译：注释一字不改，条件一字不改，只把类型换成 JS 的 `Number`。下面是 `sync` 的完整流程（**与文件里一致**）：

```text
sync(dx, dy):
    # 1. 合法性短路
    if 视窗越界或窗口尺寸 <= 0:
        return false

    # 2. 水平同步（垂直完全同理，把列换成行）
    if horizontalScrollEnabled:
        offsetX = original.offsetX + dx      # 偏移的叠加放在本方向分支内部

        # 3a. 内容未填满且已到右边界：尝试右对齐（试探性补偿）
        if contentWidth + offsetX < windowWidth 且 colEnd == rightBound:
            offsetX += windowWidth - (contentWidth + offsetX)

        # 3b. 向右拖，锚点左移，纳入新列
        while offsetX > 0 且 colStart > leftBound:
            colStart--
            w = getColWidth(colStart)
            offsetX -= w
            contentWidth += w

        # 3c. 向左拖，锚点右移，移出旧列
        startWidth = getColWidth(colStart)
        while offsetX < -startWidth 且 colStart < rightBound:
            offsetX += startWidth
            contentWidth -= startWidth
            colStart++
            startWidth = getColWidth(colStart)

        # 3c-2. 起点一跳越过结尾锚点：让结尾锚点跟着走
        if colStart > colEnd:
            colEnd = colStart
            contentWidth = startWidth

        # 3d. 已到左边界：钳位
        if offsetX > 0 且 colStart == leftBound:
            offsetX = 0

        # 3e. 内容填不满，向右扩展右锚点
        while contentWidth + offsetX < windowWidth 且 colEnd < rightBound:
            colEnd++
            contentWidth += getColWidth(colEnd)

        # 3f. 内容超出太多，收缩右锚点
        endWidth = getColWidth(colEnd)
        while contentWidth + offsetX - endWidth > windowWidth 且 colEnd > colStart:
            contentWidth -= endWidth
            colEnd--
            endWidth = getColWidth(colEnd)

        # 3g. 前面两个循环可能让右边出现空白：补掉（终态补偿）
        if contentWidth > windowWidth 且 contentWidth + offsetX < windowWidth 且 colEnd == rightBound:
            offsetX += windowWidth - (contentWidth + offsetX)

        写回 offsetX

    # 3. 垂直同步（同上，把列换成行、offsetX 换成 offsetY）

    # 4. 通知视窗计算完毕
    onWindowCalculated(colStart, rowStart, colEnd, rowEnd)

    # 5. 范围变化时更新 original 并 diff
    if 范围变化:
        更新 original
        diff(旧范围, 新范围)
```

引擎其余方法一一对应（完整代码见 `h5-demo/tile2d.js`）：

| 方法 | 作用 | 移植要点 |
|---|---|---|
| `seek(column,row,offsetX,offsetY)` | 距离无关跳转 | 累加器**从 `offsetX` 起**，末尾再减 `Math.trunc(offsetX)`（两者抵消，得到纯宽度和）；把参数当 `dx/dy` 交给 `sync` 做微调 |
| `diff` / `diffRegion` | 计算新旧视窗差异，决定谁 `in` 谁 `out` | 完全不相交时整块兜底（极端跳转靠它） |
| `updateWidth/Height/Size` | 尺寸变更后的位移补偿 | 通过 `sync(dx,0)` 走同一条路，别另写一套 |
| `isAtLeftBound` 等 | 边界判断 | 精确比较，**不留容差**（理由见下） |

**五条关键约束（翻译时不要改）**：

1. **偏移叠加放在方向分支内部**。`offsetX = original.offsetX + dx` 必须在该方向的判定与循环之前、且只在该方向生效。写成方法开头统一叠加，会让「判定里读到的 offsetX 已经含 dx」，条件退化成恒真/恒假；同时关闭滚动时也会把 dx 写进 offset，破坏下面这条不变式。
2. **不变式**：每帧结束时 `offsetX ∈ [-当前列宽, 0]`、`offsetY ∈ [-当前行高, 0]`。这是「像素精度不退化」的基础。
3. **3c-2 不是可选的**。`3c` 只移动起点锚点；一跳越过结尾锚点时，`3e` 会把刚跨过、已经扣掉的列当「新列」重新问一遍宽度（大位移下接近双倍遍历）。加上这个 `if`，跨过的列永远只问一次。
4. **能省的只有「第二遍」**。落点藏在跨过那些列的宽度之和里，变宽度数据下没有旁路（要跳 N 列就必须问 N 列），所以「跳过跑过去的过程」拿不到 O(1)。
5. **3a 与 3g 不对称是有原因的**。`3a` 是试探性补偿，推出来的偏移有下游兜底（`3b` 纳入新列消费掉，没列可纳时 `3d` 强制归零）；`3g` 是终态补偿，跑完就写快照出结果，没有下游能撤销它，必须自己先证明这一推是安全的。

**语言差异清单**（JS 侧怎么处理）：

| Java | JS | 说明 |
|---|---|---|
| `int` / `float` | `Number` | 双精度；int32 范围内精确，像素场景足够 |
| `(int) x` | `Math.trunc(x)` | 截断取整，不要用 `~~`（负数语义易错） |
| `Math.round` 语义差异 | 不用它 | Java 的 `round` 是「向下取整 + 0.5」，跨语言不一致，本项目已删掉它对 `LayoutEngine` 的依赖 |
| `TimeProvider` / `syncTime` | 无 | 调试代码，移植时整段删 |
| 接口 | 鸭子类型 | 只要对象上有 `getColWidth` / `in` / `out` 等方法即可 |

**自检点**：拿同一组输入跑 Java 与 JS，`LayoutModel` 八个字段逐位一致（做法见第 7 步）。

## 第 4 步：容器层（TileDomCore）——瓦片是真实 DOM 元素

这一步对应 Java 的 `TileLayout`（ViewGroup）。四件事：

1. **进出视窗 = 挂上/摘下元素**

```js
onTileIn(column, row) {
    const tile = this.obtain(type);           // 先从回收栈拿，拿不到才新建
    this.adapter.onBindTileHolder(tile, column, row);
    this.container.appendChild(tile.el);      // 对应 addViewInLayout
    this.active.set(key, tile);
}
onTileOut(column, row) {
    if (tile.el.parentNode === this.container) this.container.removeChild(tile.el);  // 对应 removeViewInLayout
    /* 摘下来之后进回收栈，等下次 obtain 复用 */
}
```

2. **摆放 = 一次走完可见范围，只写 style**

```js
layoutTiles() {                       // 对应 TileLayout.layoutTiles
    let x = paddingLeft + this.scale(model.offsetX);
    for (let column = model.colStart; ; column++) {
        const width = this.scale(this.getTileWidth(column));
        let y = paddingTop + this.scale(model.offsetY);
        for (let row = model.rowStart; ; row++) {
            const height = this.scale(this.getTileHeight(row));
            const tile = this.getActiveTile(column, row);
            if (tile) {               // 只有活跃瓦片才动 DOM
                tile.el.style.transform = `translate3d(${x}px,${y}px,0)`;
                tile.el.style.width = width + 'px';
                tile.el.style.height = height + 'px';
                tile.el.style.fontSize = this.scale(14) + 'px';   // 字号也随缩放
            }
            y += height;
            if (row === model.rowEnd) break;
        }
        x += width;
        if (column === model.colEnd) break;
    }
}
```

> **为什么用 `transform` 而不是 `left/top`**：`transform` 只走合成层，不触发布局重排；`left/top` 每次都让浏览器重新算布局。
> **为什么要显式 `width/height` 与 `fontSize`**：DOM 不会自己跟着缩放走——`scaleFactor` 变了就得重算（这一点和 `TileLayout` 的 `scale()` 完全一致）。

3. **缩放 = scaleFactor**（对照 `TileLayout.scale(n) = n * getScaleFactor()`）：几何与字号都乘它。容器给引擎的窗口尺寸仍然按容器尺寸算，缩放只影响「一格在屏幕上占多少像素」。

4. **命中测试 = findColumn / findRow**：把屏幕坐标换算回内容坐标（先减内边距、再除缩放），沿列/行累加宽度即可。

尺寸表沿用 `DimenManager` 的三级优先级的简化版：**单独设置 > 默认值**（演示不需要 `TileDimenProvider`）。

**自检点**：容器里的子元素数量与活跃瓦片数一致；滚动时 `transform` 被重写、滚出屏幕的元素被摘掉（可以在 DevTools 里看 DOM 树）。

## 第 5 步：数据源（noise.js）

演示数据是**确定性生成**的：固定种子柏林噪声 + 24 色渐变，与 app 瓦片 demo 同款（种子 `123456789`、缩放 `0.03`、低噪区 `< 0.3` 稀疏）。这也是「伪无限模式」能成立的前提——数据可以从任意坐标算出来，不需要预生成。

**关键：`java.util.Random` 必须逐位复刻**。柏林噪声的排列数组是用种子洗牌得来的（Fisher-Yates），洗牌结果决定每个坐标的噪声值，差一位整张图就完全不同。JS 没有 48 位整数，用 `BigInt` 实现：

```js
class JavaRandom {
    constructor(seed) { this.seed = (BigInt(seed) ^ 0x5DEECE66Dn) & 0xFFFFFFFFFFFFn; }
    next(bits) {
        this.seed = (this.seed * 0x5DEECE66Dn + 0xBn) & 0xFFFFFFFFFFFFn;
        return Number(this.seed >> BigInt(48 - bits));
    }
    nextInt(bound) {
        if ((bound & -bound) === bound) return Number((BigInt(bound) * BigInt(this.next(31))) >> 31n);
        let bits, val;
        do { bits = this.next(31); val = bits % bound; } while (bits - val + (bound - 1) < 0);
        return val;
    }
}
```

`PerlinNoise2D`（fade / lerp / 8 向梯度）与 `ColorGenerator`（24 色线性插值 + 相对亮度选文字颜色）照算法翻即可。

**自检点**：同种子下 `perm[0..15]`、若干坐标的 `noiseNormalized`、颜色、文本都与 app 端完全一致（做法见第 7 步）。

## 第 6 步：适配器与交互（main.js）

**适配器**只需四件事（对照 `TileLayout.Adapter`）：

```js
const adapter = {
    getLeftBound / getTopBound / getRightBound / getBottomBound,   // 伪无限模式时返回 int32 极值
    getTileType: (c, r) => removed.has(c + ',' + r) || noiseAt(c, r) < 0.3 ? -1 : 0,
    onCreateTileHolder: (type) => type === -1 ? null : { type, el: makeTileDiv() },
    onBindTileHolder: (holder, c, r) => { /* 背景色 + 文字颜色 + 文本 = noise/0.03 的 %.2f */ },

```

**手势**（都在 `#view` 上用 Pointer Events 实现）：

| 手势 | 实现要点 |
|---|---|
| 单指拖拽 | `dx = (当前 x - 上次 x) / scaleFactor`——除以缩放才「跟手」 |
| 惯性滚动 | 记录最近 100ms 的速度（内容像素/ms），松手后用 `v *= 0.94^(dt/16.7)` 衰减，小于阈值停 |
| 双指捏合 | 用两指距离比值得到新的 `scaleFactor`；`zoomTo(s, fx, fy)` 里用 `dx = (fx - padding) * (1/s新 - 1/s旧)` 把焦点下的内容点钉住 |
| 双击 | 300ms 内两次点击 → 1x ↔ 2x（同一个 `zoomTo`，焦点 = 点击点） |
| 长按删除 | 500ms 定时器 + 位移阈值判定 → `removed.add(key)` + `core.update(c,r)`（元素被摘掉并回收） |
| 单击 | `findColumn/findRow` 换算坐标 → Toast |
| 桌面端 | `wheel` 滚动；`Ctrl/⌘ + wheel` 缩放（`{ passive: false }` 才能 `preventDefault`） |

**菜单**对齐 app 端 `BaseActivity` 的那套：Debug 模式、伪无限模式、随机调整尺寸（宽度/高度，2 秒 overshoot 动画，作用在视窗中心那一列/行）、去边界看看（八方向 + 回到原点）、视图（放大/缩小/重置缩放）。调试模式额外给一个 HUD：窗口尺寸、视窗范围、offset、内容宽高、缩放、活跃/回收瓦片数、DOM 子元素数。

## 第 7 步：和 Java 版对齐（怎么证明移植是对的）

三件事，都在**项目外的临时目录**里做：

1. **同构差分**：让两份实现跑**同一份随机场景序列**（同一个伪随机数发生器、同一批列宽/行高/窗口/位移），逐场景比对 `LayoutModel` 的八个字段。
 本项目实测：`sync` / `seek` / `updateWidth` 混合、二维数据，4 个种子 × 150 场景 = **600 场景零差异**。
 > 注意伪随机数发生器的**乘数要小**：乘积超过 2^53 时 JS 会丢精度，两边序列会悄悄跑偏（这个坑踩过）。
2. **数据源逐位比对**：Java 端打印 `perm` 采样 + 若干坐标的 `noise`（`%.17f`）、颜色、文本，JS 端打印同样的东西，逐行比。
 本项目实测：19 个采样点噪声偏差 **0**，颜色与文本全同。
3. **不变式 + 大位移自愈**：随机游走 2000 帧，检查 `contentWidth/Height` 是否始终等于锚点跨度内各瓦片尺寸之和；`offset` 允许在「一帧跨过数据端」时短暂越界，但补一帧 `sync(0,0)` 必须自愈。

## 第 8 步：常见坑清单

1. **偏移叠加的位置**：放在方法开头，判定里的 `dx` 会被消掉——条件退化成恒真/恒假（`>=` 恒假、`<` 恒真，换符号救不了）。
2. **`seek` 的累加器初值**：必须写成 `let contentWidth = Math.trunc(offsetX);` 再在末尾 `- Math.trunc(offsetX)`——初值与减号相互抵消，得到纯宽度和。若从 0 起算、末尾仍减 `offsetX`，会整整多减一个 offset，`contentWidth` 偏小（`offsetX>0`）或偏大（`offsetX<0`），扩展循环的终止列也跟着偏一列。
3. **整数截断**：Java 的 `(int)` 对应 `Math.trunc`；负数用 `~~` 会出错。
4. **伪随机数精度**：`seed * 1103515245` 这类乘法在 JS 里超过 2^53 就丢精度，两边序列跑偏；换小乘数或上 `BigInt`。
5. **填充循环的边界**：`while (contentWidth + offsetX < windowWidth && …)` 用**严格小于**——正好填满时会再多铺一格（11 列而不是 10 列），这是引擎的既有行为，别「顺手修正」。
6. **3c-2 不能省**：省掉它大位移时接近双倍遍历，而且中间态会出现 `contentWidth` 与锚点跨度不一致。
7. **没有 64 位整数**：瓦片 key 用字符串 `"列,行"`；需要按数学值比较时再解析回两个整数。
8. **触摸细节**：容器要 `touch-action: none`；`setPointerCapture` 保证手指滑出元素仍能收到 move；`wheel` 监听必须 `{ passive: false }` 才能 `preventDefault`；`document` 上禁用 `contextmenu` 以免长按弹出菜单。
9. **别在拖拽里改 `left/top/width/height`**：只写 `transform`，尺寸只在尺寸变化时写。
