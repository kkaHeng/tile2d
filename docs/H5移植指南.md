# H5 移植指南（Tile2D）

> 本文是「跨平台移植指南」的 H5 子文档：**以项目里真实可运行的 `h5-demo/` 为例，一步步教你把 Tile2D 移植到浏览器（JavaScript）**。
> 渲染方式是 **Canvas 自绘**——视窗内的瓦片全部画在一张 `<canvas>` 上（对照 app 端 `TileView`），不做 DOM 瓦片。
> 本文的代码块都是**从 `h5-demo/` 里摘出来的真实代码**；遇到「完整代码见某文件」时，以文件为准。

## 怎么用这份指南

- **前提**：先读「跨平台移植指南」里 `LayoutEngine` 那一章（`sync` 的 3a–3g、`seek`、`diff` 的职责），本文不再重复讲原理。
- **读法**：每一步都是「要移植什么 → 真实代码长什么样 → 自检点」。
- **顺序**：先引擎（纯算法），再容器层（Canvas 绘制），最后交互与菜单——和实际写这份 demo 的顺序一致。
- **运行**：直接双击 `h5-demo/index.html`（本地 `file://` 即可，无任何网络依赖），或 `python3 -m http.server` 后访问。

## 第 0 步：先想清楚要复刻哪些东西

移植不是「把 Java 一行行抄成 JS」，而是**先分清哪部分必须逐行对齐、哪部分可以按需复刻**：

| Java 侧 | H5 侧 | 复刻程度 |
|---|---|---|
| `LayoutEngine` | `h5-demo/tile2d.js` | **逐行对齐**（含注释），行为必须完全一致 |
| `LayoutModel` | `h5-demo/tile2d.js` | 逐行对齐 |
| `TileView`（Canvas 自绘） | `TileCanvasCore`（自绘容器层） | **按需复刻**：绘制循环、缩放、命中测试、吸附 |
| `TileManager`（预取/濒死区） | —— | 演示不需要，直接砍掉 |
| `DimenManager` | `TileCanvasCore` 里的尺寸表 | 按需：逐列宽 / 逐行高 + 默认值 |
| `TileCoreService`（调度层） | `main.js` + `TileCanvasCore` | 按需：只保留演示用到的部分 |
| 柏林噪声 + 24 色渐变 | `h5-demo/noise.js` | **逐位对齐**（同种子必须出同一张图） |

一句话：**引擎和随机数要「一模一样」，容器层与调度层「照着意图重写」。**

示例共 4 个文件：

- `h5-demo/index.html` — 页面结构与样式（手机优先、安全区适配），瓦片容器就是 `<canvas id="view">`
- `h5-demo/tile2d.js` — `LayoutModel` + `LayoutEngine`（逐行对齐）+ `TileCanvasCore`（Canvas 自绘层）
- `h5-demo/noise.js` — `java.util.Random` 复刻 + 柏林噪声 + 24 色渐变
- `h5-demo/main.js` — 适配器 + 手势（惯性滚动 / 捏合缩放）+ 菜单

> **单元测试不放进工程**：本项目要求测试代码只存在于**项目外的临时目录**（也方便对着 Java 版做同构差分）。`h5-demo/tile2d.js` 底部保留 `module.exports`，就是给外部测试脚本 `require` 用的。

## 第 1 步：搭页面骨架（index.html）

瓦片容器直接就是一张 `<canvas>`（对照 app 端 `TileView` 是一块画布）：

```css
#view {
    position: fixed;
    left: 0; top: 0;
    width: 100%;
    height: 100%;
    display: block;        /* canvas 元素 */
    background: #0e1117;   /* 首帧 / 稀疏区底色 */
    touch-action: none;    /* 关键：阻止浏览器默认手势（否则拖拽会被页面滚动抢走） */
    cursor: grab;
}
```

手机适配的三件事：`<meta name="viewport" … viewport-fit=cover>`、用 `env(safe-area-inset-*)` 给顶栏/底栏留安全区、`html,body { overflow: hidden; overscroll-behavior: none; }` 防止整页橡皮筋。

页面结构（完整见 `h5-demo/index.html`）：`#view`（自绘画布）+ `#topbar`（状态胶囊 + 菜单键）+ `#hud`（调试面板）+ `#toast` + `#sheet`（底部抽屉菜单）。

**画布的「高清」处理**：`<canvas>` 的后备缓冲要按设备像素比放大，绘制坐标仍用 CSS 像素（`TileCanvasCore.resizeCanvas` 里做）：

```js
resizeCanvas() {
    const w = Math.max(1, Math.round(this.containerWidth * this.dpr));
    const h = Math.max(1, Math.round(this.containerHeight * this.dpr));
    if (this.canvas.width !== w) this.canvas.width = w;
    if (this.canvas.height !== h) this.canvas.height = h;
}
// 绘制前：ctx.setTransform(this.dpr, 0, 0, this.dpr, 0, 0)
```

**自检点**：页面能在手机上打开、拖拽时页面不会跟着滚、画布四边贴合屏幕（含刘海屏安全区）、放大看瓦片与文字不模糊。

## 第 2 步：布局模型（LayoutModel）

引擎要两个模型：`original` 记录真实状态，`output` 是给外部读的快照。对照 Java 的 `LayoutModel`：

```js
class LayoutModel {
    constructor() {
        this.colStart = 0; this.rowStart = 0;
        this.colEnd = -1; this.rowEnd = -1;      // 空区间：[0,-1]
        this.offsetX = 0; this.offsetY = 0;
        this.contentWidth = 0; this.contentHeight = 0;
    }
    copyTo(m) { /* 八个字段整体拷贝 */ }
    newInstance() { const m = new LayoutModel(); this.copyTo(m); return m; }
    reset() { /* 回到空区间 */ }
}
```

**自检点**：`colEnd = -1`、`rowEnd = -1` 表示「还没有任何内容」，引擎的合法性短路会用到这个约定。

## 第 3 步：布局引擎（LayoutEngine）——必须逐行对齐

引擎是整份移植里唯一「不能自己发挥」的部分。`h5-demo/tile2d.js` 里那 500 行就是 Java 版的同构翻译：注释一字不改，条件一字不改，只把类型换成 JS 的 `Number`。下面是 `sync` 的完整流程（**与文件里一致**）：

```text
sync(dx, dy):
    # 1. 合法性短路
    if 视窗越界或窗口尺寸 <= 0:
        return false

    # 2. 水平同步（垂直完全同理，把列换成行）
    if horizontalScrollEnabled:
        offsetX = original.offsetX + dx      # 偏移的叠加放在本方向分支内部

        # 3a. 内容未填满且已到右边界：尝试右对齐（试探性补偿）
        if contentWidth + offsetX < windowWidth 且 colEnd == rightBound:
            offsetX += windowWidth - (contentWidth + offsetX)

        # 3b. 向右拖，锚点左移，纳入新列
        while offsetX > 0 且 colStart > leftBound:
            colStart--
            w = getColWidth(colStart)
            offsetX -= w
            contentWidth += w

        # 3c. 向左拖，锚点右移，移出旧列
        startWidth = getColWidth(colStart)
        while offsetX < -startWidth 且 colStart < rightBound:
            offsetX += startWidth
            contentWidth -= startWidth
            colStart++
            startWidth = getColWidth(colStart)

        # 3c-2. 起点一跳越过结尾锚点：让结尾锚点跟着走
        if colStart > colEnd:
            colEnd = colStart
            contentWidth = startWidth

        # 3d. 已到左边界：钳位
        if offsetX > 0 且 colStart == leftBound:
            offsetX = 0

        # 3e. 内容填不满，向右扩展右锚点
        while contentWidth + offsetX < windowWidth 且 colEnd < rightBound:
            colEnd++
            contentWidth += getColWidth(colEnd)

        # 3f. 内容超出太多，收缩右锚点
        endWidth = getColWidth(colEnd)
        while contentWidth + offsetX - endWidth > windowWidth 且 colEnd > colStart:
            contentWidth -= endWidth
            colEnd--
            endWidth = getColWidth(colEnd)

        # 3g. 前面两个循环可能让右边出现空白：补掉（终态补偿）
        if contentWidth > windowWidth 且 contentWidth + offsetX < windowWidth 且 colEnd == rightBound:
            offsetX += windowWidth - (contentWidth + offsetX)

        写回 offsetX

    # 3. 垂直同步（同上，把列换成行、offsetX 换成 offsetY）

    # 4. 通知视窗计算完毕
    onWindowCalculated(colStart, rowStart, colEnd, rowEnd)

    # 5. 范围变化时更新 original 并 diff
    if 范围变化:
        更新 original
        diff(旧范围, 新范围)
```

引擎其余方法一一对应（完整代码见 `h5-demo/tile2d.js`）：

| 方法 | 作用 | 移植要点 |
|---|---|---|
| `seek(column,row,offsetX,offsetY)` | 距离无关跳转 | 累加器**从 `offsetX` 起**，末尾再减 `Math.trunc(offsetX)`（两者抵消，得到纯宽度和）；把参数当 `dx/dy` 交给 `sync` 做微调 |
| `diff` / `diffRegion` | 计算新旧视窗差异，决定谁 `in` 谁 `out` | 完全不相交时整块兜底（极端跳转靠它） |
| `updateWidth/Height/Size` | 尺寸变更后的位移补偿 | 通过 `sync(dx,0)` 走同一条路，别另写一套 |
| `isAtLeftBound` 等 | 边界判断 | 精确比较，**不留容差**（理由见下） |

**五条关键约束（翻译时不要改）**：

1. **偏移叠加放在方向分支内部**。`offsetX = original.offsetX + dx` 必须在该方向的判定与循环之前、且只在该方向生效。写成方法开头统一叠加，会让「判定里读到的 offsetX 已经含 dx」，条件退化成恒真/恒假；同时关闭滚动时也会把 dx 写进 offset，破坏下面这条不变式。
2. **不变式**：每帧结束时 `offsetX ∈ [-当前列宽, 0]`、`offsetY ∈ [-当前行高, 0]`。这是「像素精度不退化」的基础。
3. **3c-2 不是可选的**。`3c` 只移动起点锚点；一跳越过结尾锚点时，`3e` 会把刚跨过、已经扣掉的列当「新列」重新问一遍宽度（大位移下接近双倍遍历）。加上这个 `if`，跨过的列永远只问一次。
4. **能省的只有「第二遍」**。落点藏在跨过那些列的宽度之和里，变宽度数据下没有旁路（要跳 N 列就必须问 N 列），所以「跳过跑过去的过程」拿不到 O(1)。
5. **3a 与 3g 不对称是有原因的**。`3a` 是试探性补偿，推出来的偏移有下游兜底（`3b` 纳入新列消费掉，没列可纳时 `3d` 强制归零）；`3g` 是终态补偿，跑完就写快照出结果，没有下游能撤销它，必须自己先证明这一推是安全的。

**语言差异清单**（JS 侧怎么处理）：

| Java | JS | 说明 |
|---|---|---|
| `int` / `float` | `Number` | 双精度；int32 范围内精确，像素场景足够 |
| `(int) x` | `Math.trunc(x)` | 截断取整，不要用 `~~`（负数语义易错） |
| `Math.round` 语义差异 | 不用它 | Java 的 `round` 是「向下取整 + 0.5」，跨语言不一致，本项目已删掉它对 `LayoutEngine` 的依赖 |
| `TimeProvider` / `syncTime` | 无 | 调试代码，移植时整段删 |
| 接口 | 鸭子类型 | 只要对象上有 `getColWidth` / `in` / `out` 等方法即可 |

**自检点**：拿同一组输入跑 Java 与 JS，`LayoutModel` 八个字段逐位一致（做法见第 7 步）。

## 第 4 步：容器层（TileCanvasCore）——Canvas 自绘

这一步对应 Java 的 `TileView`（一块画布）。核心是**一次绘制循环** + 一份**绘制信息缓存**。

**① 进出视窗只维护缓存，不碰 DOM**

引擎的 `in/out` 不再增删元素，只把「该格怎么画」缓存起来；稀疏区存 `null`，绘制时跳过、露出底色：

```js
onTileIn(column, row) {
    const type = this.adapter.getTileType(column, row);
    this.paints.set(TileCanvasCore.key(column, row),
        type === -1 ? null : this.adapter.getPaint(column, row));
}
onTileOut(column, row) {
    this.paints.delete(TileCanvasCore.key(column, row));
}
```

**② 绘制 = 清屏 + 沿视窗逐格画矩形/边框/文本**

```js
draw() {
    ctx.setTransform(this.dpr, 0, 0, this.dpr, 0, 0);
    ctx.fillStyle = this.background;      // 先铺底色（稀疏区/空白就露它）
    ctx.fillRect(0, 0, this.containerWidth, this.containerHeight);

    let x = this.paddingLeft + model.offsetX * scale;
    for (let column = model.colStart; ; column++) {
        const w = this.getTileWidth(column) * scale;
        let y = this.paddingTop + model.offsetY * scale;
        for (let row = model.rowStart; ; row++) {
            const h = this.getTileHeight(row) * scale;
            const paint = this.getPaint(column, row);
            if (paint) {
                ctx.fillStyle = paint.color;  ctx.fillRect(x, y, w, h);
                ctx.strokeStyle = '#808080';  ctx.strokeRect(x, y, w, h);   // 0.5px 边框
                ctx.fillStyle = paint.textColor;
                ctx.fillText(paint.text, x + w / 2, y + h / 2);             // 居中文本
            }
            y += h; if (row === model.rowEnd) break;
        }
        x += w; if (column === model.colEnd) break;
    }
}
```

**③ 缩放 = scaleFactor，且引擎窗口要按缩放换算**

几何与字号都乘 `scaleFactor`（等价于 `TileView` 的 `scale(n) = n * getScaleFactor()`）。**关键**：引擎的窗口单位是「内容像素」，所以给引擎的窗口 = `(容器尺寸 - 内边距) ÷ scaleFactor`（对照 `TileCoreService.updateWindowSize`）：

```js
const scale = this.scaleFactor || 1;
this.viewportWidth  = Math.max(1, Math.round((this.containerWidth  - this.paddingLeft * 2) / scale));
this.viewportHeight = Math.max(1, Math.round((this.containerHeight - this.paddingTop  * 2) / scale));
```

**④ 跳转要清缓存、越界要吸附**

- `seek` 是「重置视窗」：先把绘制缓存清掉再让引擎重建（对照 `TileCoreService.seek` 里的 `clearActiveAndDying`）。
- `snap` 是「越界时跳到最近合法锚点」，**不能只写 `sync(0,0)`**（越界时 `sync` 会合法性短路、什么都不做）：

```js
snap() {
    if (this.isEmpty()) return;
    const m = this.getLayoutModel();
    if (m.colStart >= left && m.colEnd <= right && m.rowStart >= top && m.rowEnd <= bottom) return;
    this.seek(Math.max(left, Math.min(m.colStart, right)),
              Math.max(top,  Math.min(m.rowStart, bottom)), 0, 0);
}
```

**⑤ 命中测试 = findColumn / findRow**：把屏幕坐标换算回内容坐标（先减内边距、再除缩放），沿列/行累加宽度即可。

尺寸表沿用 `DimenManager` 三级优先级的简化版：**单独设置 > 默认值**（演示不需要 `TileDimenProvider`）。

**自检点**：单次绘制画出的格子数 == 视窗内的格子数；稀疏区确实没画；跳转后不残留旧画面；缩放后不留白、不超出。

## 第 5 步：数据源（noise.js）

演示数据是**确定性生成**的：固定种子柏林噪声 + 24 色渐变，与 app 瓦片 demo 同款（种子 `123456789`、缩放 `0.03`、低噪区 `< 0.3` 稀疏）。这也是「伪无限模式」能成立的前提——数据可以从任意坐标算出来，不需要预生成。

**关键：`java.util.Random` 必须逐位复刻**。柏林噪声的排列数组是用种子洗牌得来的（Fisher-Yates），洗牌结果决定每个坐标的噪声值，差一位整张图就完全不同。JS 没有 48 位整数，用 `BigInt` 实现：

```js
class JavaRandom {
    constructor(seed) { this.seed = (BigInt(seed) ^ 0x5DEECE66Dn) & 0xFFFFFFFFFFFFn; }
    next(bits) {
        this.seed = (this.seed * 0x5DEECE66Dn + 0xBn) & 0xFFFFFFFFFFFFn;
        return Number(this.seed >> BigInt(48 - bits));
    }
    nextInt(bound) {
        if ((bound & -bound) === bound) return Number((BigInt(bound) * BigInt(this.next(31))) >> 31n);
        let bits, val;
        do { bits = this.next(31); val = bits % bound; } while (bits - val + (bound - 1) < 0);
        return val;
    }
}
```

`PerlinNoise2D`（fade / lerp / 8 向梯度）与 `ColorGenerator`（24 色线性插值 + 相对亮度选文字颜色）照算法翻即可。

**自检点**：同种子下 `perm[0..15]`、若干坐标的 `noiseNormalized`、颜色、文本都与 app 端完全一致（做法见第 7 步）。

## 第 6 步：适配器与交互（main.js）

**适配器**只需「边界 + 类型 + 怎么画」（对照 `TileView.Adapter`）：

```js
const adapter = {
    getLeftBound / getTopBound / getRightBound / getBottomBound,  // 伪无限模式时返回 int32 极值
    // 低噪区稀疏：返回 -1 表示这一格不画
    getTileType: (column, row) => noiseAt(column, row) < 0.3 ? -1 : 0,
    // 自绘要的数据：背景色 + 文字颜色 + 文本
    getPaint: (column, row) => {
        const noise = noiseAt(column, row);
        const color = colorGen.getColor((noise - 0.3) / 0.7);
        return {
            color: ColorGenerator.css(color),
            textColor: ColorGenerator.luminance(color) > 0.40 ? '#111111' : '#ffffff',
            text: (noise / 0.03).toFixed(2),
        };
    },
};
```

**手势**（都在画布上用 Pointer Events 实现，鼠标/触摸通用）：

| 手势 | 实现要点 |
|---|---|
| 拖动（触摸/鼠标） | `dx = (当前 x - 上次 x) / scaleFactor`——除以缩放才「跟手」 |
| 惯性滚动 | 记录最近 100ms 的速度（内容像素/ms），松手后用 `v *= 0.94^(dt/16.7)` 衰减，小于阈值停 |
| 双指捏合 | 用两指距离比值得到新的 `scaleFactor`；`zoomTo(s, fx, fy)` 里用 `dx = (fx - padding) * (1/s新 - 1/s旧)` 把焦点下的内容点钉住 |
| 双击 | 300ms 内两次点击 → 1x ↔ 2x（同一个 `zoomTo`，焦点 = 点击点） |
| 单击 | `findColumn/findRow` 换算坐标 → Toast（不设长按） |
| 滚轮 | 只保留 `Ctrl/⌘ + wheel` 缩放（`{ passive: false }` 才能 `preventDefault`） |

**菜单**对齐 app 端 `BaseActivity` 的那套：Debug 模式、伪无限模式、随机调整尺寸（宽度/高度，2 秒 overshoot 动画，作用在**视窗中心那一列/行**）、去边界看看（八方向 + 回到原点）、视图（放大/缩小/重置缩放）。调试模式额外给一个 HUD：窗口尺寸、视窗范围、offset、内容宽高、缩放、画布尺寸、缓存格数。

> 小细节：菜单项点完自动收起（像原生菜单），否则底部抽屉会盖住屏幕中心，看不到随机尺寸动效；中心列/行用**引擎自己的窗口几何**算（`padding + viewport*scale/2`），和画出来的视窗同源，不会错位。

## 第 7 步：和 Java 版对齐（怎么证明移植是对的）

三件事，都在**项目外的临时目录**里做：

1. **同构差分**：让两份实现跑**同一份随机场景序列**（同一个伪随机数发生器、同一批列宽/行高/窗口/位移），逐场景比对 `LayoutModel` 的八个字段。
 本项目实测：`sync` / `seek` / `updateWidth` 混合、二维数据，4 个种子 × 150 场景 = **600 场景零差异**。
 > 注意伪随机数发生器的**乘数要小**：乘积超过 2^53 时 JS 会丢精度，两边序列会悄悄跑偏（这个坑踩过）。
2. **数据源逐位比对**：Java 端打印 `perm` 采样 + 若干坐标的 `noise`（`%.17f`）、颜色、文本，JS 端打印同样的东西，逐行比。
 本项目实测：19 个采样点噪声偏差 **0**，颜色与文本全同。
3. **不变式 + 大位移自愈**：随机游走 2000 帧，检查 `contentWidth/Height` 是否始终等于锚点跨度内各瓦片尺寸之和；`offset` 允许在「一帧跨过数据端」时短暂越界，但补一帧 `sync(0,0)` 必须自愈。

## 第 8 步：常见坑清单

**引擎侧**：

1. **偏移叠加的位置**：放在方法开头，判定里的 `dx` 会被消掉——条件退化成恒真/恒假（`>=` 恒假、`<` 恒真，换符号救不了）。
2. **`seek` 的累加器初值**：必须写成 `let contentWidth = Math.trunc(offsetX);` 再在末尾 `- Math.trunc(offsetX)`——初值与减号相互抵消，得到纯宽度和。若从 0 起算、末尾仍减 `offsetX`，会整整多减一个 offset，`contentWidth` 偏小（`offsetX>0`）或偏大（`offsetX<0`），扩展循环的终止列也跟着偏一列。
3. **整数截断**：Java 的 `(int)` 对应 `Math.trunc`；负数用 `~~` 会出错。
4. **伪随机数精度**：`seed * 1103515245` 这类乘法在 JS 里超过 2^53 就丢精度，两边序列跑偏；换小乘数或上 `BigInt`。
5. **填充循环的边界**：`while (contentWidth + offsetX < windowWidth && …)` 用**严格小于**——正好填满时会再多铺一格（11 列而不是 10 列），这是引擎的既有行为，别「顺手修正」。
6. **3c-2 不能省**：省掉它大位移时接近双倍遍历，而且中间态会出现 `contentWidth` 与锚点跨度不一致。
7. **没有 64 位整数**：瓦片 key 用字符串 `"列,行"`；需要按数学值比较时再解析回两个整数。

**渲染 / 交互侧**：

8. **`snap` 不能只是 `sync(0,0)`**：越界时 `sync` 会直接短路返回，什么都不做（伪无限模式关闭后视窗没被拉回来，就是这么漏的）。越界要 `seek` 到最近合法锚点。
9. **换缩放必须重算引擎窗口**：窗口 = `(容器尺寸 - 内边距) ÷ scaleFactor`。不除缩放 → `scale>1` 时「超出屏幕不回收」、`scale<1` 时「留白」。
10. **`seek` 要先清绘制缓存**：引擎的 `in/out` 只管缓存，`seek` 前不 `clear` 就会残留旧画面的缓存。
11. **画布高清**：后备缓冲按 `devicePixelRatio` 放大，绘制前 `ctx.setTransform(dpr,0,0,dpr,0,0)`，坐标仍用 CSS 像素；否则糊、且鼠标坐标与画面错位。
12. **别只 `clearRect` 了事**：要先 `fillRect` 铺底色，稀疏区/空白才能露出底色。
13. **别每帧读 `getBoundingClientRect()`**：容器矩形缓存起来，只在尺寸变化（resize / 转屏）时重读，否则每个触摸事件都可能强制同步布局。
14. **触摸细节**：容器要 `touch-action: none`；`setPointerCapture` 保证手指滑出画布仍能收到 move；`wheel` 监听必须 `{ passive: false }` 才能 `preventDefault`；`document` 上禁用 `contextmenu`。
