# H5 移植指南（Tile2D）

> 本文是「跨平台移植指南」的 H5 子文档。目标平台：浏览器（JavaScript）。渲染方式：**DOM**——瓦片是真实元素，不做 Canvas 自绘。完整可运行示例在项目根目录 `h5-demo/`（5 个文件）。本文代码块只贴**关键片段**作示意，**完整代码一律以 `h5-demo/` 下的文件为准**。

## 总览

- 环境：原生 JavaScript（ES6），无框架、无构建工具，`<script>` 引入即可运行
- 渲染：瓦片是真实 `div`，绝对定位摆放；内容层用 `transform` 承载像素偏移
- 模块与 Java 版一一对应：`LayoutModel` / `LayoutEngine` / `TileManager` / `DimenManager` / `TileCoreService` / 视图层
- 演示玩法与 app 瓦片画板 demo 同款：**伪无限模式**（边界扩展至完整 int32 空间）与**去边界看看**（随机跳转 8 个极端点），数据由固定种子柏林噪声生成
- 与 Java 版的关键差异：
  - **没有 64 位整数**：JS 的位运算只有 32 位，瓦片 ID 用字符串 `"列,行"` 作 key
  - **没有装箱问题**：活跃/濒死瓦片直接用 `Map`，不需要自定义哈希表
  - `Math.min/max` 替代重载；`Number` 是双精度，int32 范围内精确
  - **预取未移植**：方向预测预取（`diffPrefetch`/`drainPrefetch`）是 Java 版新增能力，H5 版暂未实现；尺寸删除语义已同步（`setTileWidth` 要求大于 0，删除走 `deleteTileWidth`）

## 第四步：布局引擎（LayoutEngine）完整移植

引擎是移植的重点，要求**完整实现**：视窗计算、像素精度、边界行为全部在这里，任何一行边界条件改动都会导致滚动行为与 Java 版不一致。

引擎只依赖两个接口（边界、视窗交互），JS 里用鸭子类型即可，不需要显式接口。对齐常量与 Java 版一致：`DIMEN_GRAVITY_CENTER = 0`、`DIMEN_GRAVITY_START = -1`、`DIMEN_GRAVITY_END = 1`。

`sync` 的流程（与跨平台指南伪代码一致）：合法性短路 → 偏移叠加 → 水平同步（右对齐/锚点左移/锚点右移/钳位/右锚点扩展/右锚点收缩）→ 垂直同步 → 写快照 → 通知视窗计算完毕 → 范围变化时 diff。关键约束：`offsetX` 始终保持在 `[-当前列宽, 0]`，`offsetY` 保持在 `[-当前行高, 0]`。

`diff` 保留了「完全不相交」分支：极端跳转（如 `seek` 跨越整个 int32 空间）时旧范围整体 `out`、新范围整体 `in`，否则逐格判断会死循环。伪无限模式的「去边界看看」正是靠这个分支保证安全。

`sync` 的水平同步（锚点移动 + 列宽累加）：

```js
// 3b. 向右拖，锚点左移，纳入新列
while (offsetX > 0 && colStart > leftBound) {
    colStart--;
    const w = this.window.getColWidth(colStart);
    offsetX -= w;
    totalWidth += w;
}
// 3c. 向左拖，锚点右移，移出旧列
let startWidth = this.window.getColWidth(colStart);
while (offsetX < -startWidth && colStart < rightBound) {
    offsetX += startWidth;
    totalWidth -= startWidth;
    colStart++;
    startWidth = this.window.getColWidth(colStart);
}
```

`diff` 的「完全不相交」分支：

```js
if (newColStart > oldColEnd || newRowStart > oldRowEnd ||
    newColEnd < oldColStart || newRowEnd < oldRowStart) {
    // 完全不相交：旧范围全部 out，新范围全部 in
    for (let x = oldColStart; x <= oldColEnd; x++) {
        for (let y = oldRowStart; y <= oldRowEnd; y++) this.window.out(x, y);
    }
    for (let x = newColStart; x <= newColEnd; x++) {
        for (let y = newRowStart; y <= newRowEnd; y++) this.window.in(x, y);
    }
    return;
}
```

> 完整实现见 `h5-demo/tile2d.js`（sync / seek / diff / 尺寸补偿等，行为与 Java 版完全一致，由 25 项 node 单测保证）。

## 第五步：瓦片管理器（TileManager）

三状态池（活跃/濒死/回收）+ 生命周期 + 更新操作，与 Java 版结构一致。两个 JS 特有的实现点：

- 瓦片 key 用 `column + ',' + row` 字符串（见总览说明）
- 濒死区边界用**逐格行走**而不是减法，避免 `Integer.MIN_VALUE` 附近溢出（JS 数字虽然是双精度，但边界语义要保持与 Java 一致）

```js
class TileManager {
    // 瓦片 key：字符串 "列,行"
    static key(column, row) { return column + ',' + row; }

    in(column, row) {
        const key = TileManager.key(column, row);
        let tile = this.dying.get(key);
        if (tile) {
            // 从濒死池复用，跳过绑定
            this.dying.delete(key);
        } else {
            const type = this.callback.getTileType(column, row);
            tile = this.obtain(type);
            if (tile) {
                tile.column = column; tile.row = row;
                tile.width = this.callback.getTileWidth(column);
                tile.height = this.callback.getTileHeight(row);
                this.callback.onBindTileHolder(tile, column, row);
            }
        }
        if (tile) {
            this.active.set(key, tile);
            if (tile.onInWindow) tile.onInWindow();
            this.callback.onTileIn(tile, column, row);
        }
    }
    // 濒死区边界用逐格行走、更新操作等，见 h5-demo/tile2d.js
}
```

> 完整实现见 `h5-demo/tile2d.js`。

## 第六步：尺寸管理器（DimenManager）

三级优先级：单独设置 > 尺寸提供者 > 默认值。修改尺寸时同步濒死区内瓦片、做视窗补偿、触发刷新：

```js
// 三级优先级：单独设置 > 尺寸提供者 > 默认值
getTileWidth(column) {
    if (this.widths.has(column)) return this.widths.get(column);
    if (this.dimenProvider) return this.dimenProvider.getTileWidth(column);
    return this.defaultTileWidth;
}
```

> 完整实现见 `h5-demo/tile2d.js`。

## 第七步：核心调度层（TileCoreService）

把三个模块接起来，实现四组接口（边界、视窗、瓦片回调、尺寸回调），对外暴露统一 API。视图层只与它打交道：

```js
class TileCoreService {
    constructor(coreInterface) {
        this.core = coreInterface;
        this.layoutEngine = new LayoutEngine(this, this);
        this.tileManager = new TileManager(this);
        this.dimenManager = new DimenManager(this);
        this.bounds = { left: 0, top: 0, right: 0, bottom: 0 };
    }
    // ---- 布局引擎的边界接口 ----
    getLeftBound() { return this.core.getLeftBound(); }
    // ---- 布局引擎的视窗接口 ----
    in(column, row) { this.tileManager.in(column, row); }
    getColWidth(column) { return this.dimenManager.getTileWidth(column); }
    // 其余接口与统一 API 见 h5-demo/tile2d.js
}
```

> 完整实现见 `h5-demo/tile2d.js`。

## 第八步：DOM 渲染层（Tile2DView）

为什么用 DOM 而不是 Canvas：`div` 天然支持点击、hover、样式、动画，瓦片就是真实元素，内容型页面（文本、图片、表单）可以直接塞进瓦片，不需要自己实现命中测试。

结构分两层：

```text
容器 #view（relative + overflow: hidden）
└─ 内容层 div（absolute，transform: translate(offsetX, offsetY)）
    └─ 瓦片 div（absolute，left/top = 累加坐标）
```

- **偏移用 `transform`**：不触发 reflow，且 `offset` 是像素级浮点数，`transform` 能精确表达
- **瓦片定位用 `left/top`**：逐格累加列宽/行高，可变尺寸天然支持
- `onTileIn` 把瓦片元素挂进内容层，`onTileOut/onTileRecycled` 移除
- 输入：指针拖拽 `sync(dx, dy)`（手指向右 → 内容向右 → offset 增加）；滚轮 `sync(-deltaX, -deltaY)`

```js
// 内容层：绝对定位 + transform 承载 offset，瓦片按累加坐标绝对定位
this.content = document.createElement('div');
this.content.style.position = 'absolute';
this.content.style.left = this.paddingLeft + 'px';
this.content.style.top = this.paddingTop + 'px';
this.content.style.transformOrigin = '0 0';
container.appendChild(this.content);
// 瓦片进出回调（onTileIn / onTileOut），见 h5-demo/tile2d.js
onTileIn: (holder) => { this.content.appendChild(holder.el); },
onTileOut: (holder) => { holder.el.remove(); },
```

> 完整实现见 `h5-demo/tile2d.js`。

## 第九步：噪声纹理（noise.js）

演示数据是**确定性生成**的，不依赖任何服务端：固定种子柏林噪声 + 24 色渐变映射，与 app 瓦片画板 demo 同款（种子 `123456789`、缩放 `0.03`、低噪区 `< 0.3` 稀疏）。这正是「伪无限模式」能成立的前提——数据可以从任意坐标计算出来，不需要预生成。

`createRandom` 是 32 位 SplitMix64，保证同一种子洗牌结果可复现；`PerlinNoise2D` 与 Java 版逐行对应（8 向梯度、fade 插值）；`colorFromNoise` 在 24 色之间线性插值，`luminance` 用于选择前景文字颜色：

```js
// 确定性随机数（SplitMix64，32位版）：保证同一种子洗牌结果可复现
function createRandom(seed) {
    let x = seed >>> 0;
    return function () {
        x = (x + 0x9E3779B9) >>> 0;
        let z = x;
        z = Math.imul(z ^ (z >>> 16), 0x21F0AAAD);
        z = Math.imul(z ^ (z >>> 15), 0x735A2D97);
        return (z ^ (z >>> 15)) >>> 0;
    };
}
// COLOR_TABLE（24 色渐变）与 colorFromNoise / luminance，见 h5-demo/noise.js
```

> 完整文件见 `h5-demo/noise.js`。

## 第十步：适配器与演示逻辑（main.js）

适配器与 Java 版同一个形状：边界、创建、绑定、类型。三个演示要点：

- **柏林噪声映射**：`getTileType` 用噪声 `< 0.3` 判定稀疏；`onBindTileHolder` 把 `(噪声 - 0.3) / 0.7` 映射到 24 色渐变
- **伪无限模式**：边界在有限范围与 `±2147483647` 之间切换，切换后调 `snap()` 把视窗拉回合法范围
- **去边界看看**：随机选 8 个极端点之一跳转（与 app demo 同款：最上边/右上角/最右边/右下角/最下边/左下角/最左边/左上角）

```js
const adapter = {
    getLeftBound: () => maxMode ? MIN_INT : -50,
    getTopBound: () => maxMode ? MIN_INT : -100,
    getRightBound: () => maxMode ? MAX_INT : 50,
    getBottomBound: () => maxMode ? MAX_INT : 100,
    getTileType: (column, row) =>
        perlin.noiseNormalized(column * 0.03, row * 0.03) < 0.3 ? -1 : 0, // 低噪区稀疏
    ...
};
// 伪无限模式：边界在 int32 全范围与有限范围之间切换，切换后 snap 拉回视窗
bind('btn-max', () => {
    maxMode = !maxMode;
    view.snap();
    ...
});
// 去边界看看等按钮逻辑，见 h5-demo/main.js
```

## 第十一步：运行与验证

- 浏览器：直接打开 `h5-demo/index.html`（本地 `file://` 即可，无任何网络依赖），或 `python3 -m http.server` 后访问
- node 单测：`node h5-demo/test.js`，引擎与噪声都不依赖 DOM，可以脱离浏览器验证

单测固定尺寸（列宽 80、行高 45）与固定视窗（800x450），所有期望值都可以手算出来——这正是纯算法引擎的好处：

```js
// 固定尺寸：列宽 80，行高 45；视窗 800x450
engine.seek(0, 0, 0, 0);
let m = engine.getLayoutModel();
assert(m.colStart === 0 && m.rowStart === 0, 'seek(0,0) 锚点为原点');
engine.sync(-400, -225);
m = engine.getLayoutModel();
assert(m.colStart === 4 && m.rowStart === 4, '左移 400px 锚点变 (4,4)');
assert(m.offsetX === -80 && m.offsetY === -45, 'offset 余 (-80,-45)');
```

> 完整测试见 `h5-demo/test.js`（25 项断言，含伪无限回归与噪声边界）。测试要点：左移 400px 恰好 5 列，锚点变 4、offset 余 -80；`seek(99,99)` 内容填不满视窗，锚点自动回填到 90；加宽第 0 列后右侧自动少一列；噪声同种子可复现、int32 边界处采样正常。这些行为与 Java 版完全一致。
