# 安卓平台扩展指南

对`TileView`、`TileLayout`不满意可以自己实现，这里教你怎么一步步对接。你可以**自定义View**、**转Compose**、**转OpenGL ES**等等。

## 自定义View

这个最简单，你可以直接复用所有底层组件和核心服务，只需要`extends View`或`extends ViewGroup`并对接核心服务即可，核心服务已经关联起了所有底层组件。

思路拆开就四件事：**创建核心服务**、**实现接口**、**对接生命周期**、**接适配器**。核心服务是唯一入口，`LayoutEngine`、`TileManager`、`DimenManager`、`EventHandler` 全部由它调度，你不需要直接碰它们。

#### 第一步：创建核心服务

`TileCoreService` 构造需要两个参数：`Context` 和 `CoreInterface`。`CoreInterface` 是视图层与核心层的全部契约，让自定义 View 自己实现即可：

```java
public class MyTileView extends View implements TileCoreService.CoreInterface<MyHolder> {

    private TileCoreService<MyHolder> coreService;
    private MyAdapter adapter;

    public MyTileView(Context context) {
        super(context);
        coreService = new TileCoreService<>(context, this);
        coreService.setDefaultTileWidth(80);   // 默认列宽，按业务调整
        coreService.setDefaultTileHeight(45);  // 默认行高
    }
}
```

#### 第二步：实现 CoreInterface

接口一共三类方法，全部需要实现：**布局回调**、**瓦片生命周期**、**数据查询**。骨架如下，照抄即可：

```java
// ===== 布局回调 =====

@Override
public void updateUI() {
    // 布局完成，触发重绘
    postInvalidateOnAnimation();
}

@Override
public void beforeLayout() {
    // 布局开始前回调（可选，一般留空）
}

// ===== 瓦片生命周期 =====

@Override
public void onTileIn(MyHolder holder, int column, int row) {
    // 瓦片进入视窗
}

@Override
public void onTileOut(MyHolder holder, int column, int row) {
    // 瓦片离开视窗
}

@Override
public void onTileRecycled(MyHolder holder, int column, int row) {
    // 瓦片被回收，释放资源
}

@Override
public void onTileSizeChanged(MyHolder holder, int column, int row, int width, int height) {
    // 瓦片尺寸变化（可选）
}

// ===== 数据查询（委托给适配器） =====

@Override
public int getLeftBound()   { return adapter == null ? 0 : adapter.getLeftBound(); }
@Override
public int getTopBound()    { return adapter == null ? 0 : adapter.getTopBound(); }
@Override
public int getRightBound()  { return adapter == null ? -1 : adapter.getRightBound(); }
@Override
public int getBottomBound() { return adapter == null ? -1 : adapter.getBottomBound(); }

@Override
public MyHolder onCreateTileHolder(int type) {
    return adapter.onCreateTileHolder(type);
}

@Override
public void onBindTileHolder(MyHolder holder, int column, int row) {
    adapter.onBindTileHolder(holder, column, row);
}

@Override
public int getTileType(int column, int row) {
    return adapter.getTileType(column, row);
}
```

> 空适配器约定：没有适配器时左/上边界返回 `0`、右/下边界返回 `-1`，这样 `left > right` 立即判空，核心服务不会产生任何瓦片。

#### 第三步：对接 View 生命周期

尺寸、绘制、触摸、滚动四个入口必须接到核心服务上，缺一个都会出问题：

```java
@Override
protected void onSizeChanged(int w, int h, int oldw, int oldh) {
    super.onSizeChanged(w, h, oldw, oldh);
    // 视窗边界 = 内容区（含内边距），必须与绘制坐标系一致
    coreService.setBounds(getPaddingLeft(), getPaddingTop(),
            getWidth() - getPaddingRight(), getHeight() - getPaddingBottom());
    if (getWidth() != 0 && getHeight() != 0) {
        coreService.sync(0, 0); // 尺寸变化后强制重新同步视窗
    }
}

@Override
public boolean onTouchEvent(MotionEvent event) {
    if (coreService.isEmpty()) return super.onTouchEvent(event);
    coreService.handleTouchEvent(event); // 手势、滚动、惯性全部交给核心服务
    return true;
}

@Override
public void computeScroll() {
    super.computeScroll();
    coreService.computeScroll(); // 惯性滚动逐帧驱动
}

@Override
protected void onDetachedFromWindow() {
    super.onDetachedFromWindow();
    coreService.resetAnimator(); // 离开窗口立即停止动画，避免泄漏
}
```

> `setBounds` 的四个值直接决定瓦片能铺多大，必须和 `onDraw` 里使用的坐标系一致，否则点击、绘制、滚动会整体错位。

#### 第四步：绘制瓦片

自绘场景的绘制流程：**取模型 → 遍历可见范围 → 逐个绘制**：

```java
@Override
protected void onDraw(Canvas canvas) {
    super.onDraw(canvas);
    LayoutModel model = coreService.getLayoutModel();
    if (model.colStart > model.colEnd || model.rowStart > model.rowEnd) {
        return; // 空视窗
    }

    canvas.save();
    canvas.translate(getPaddingLeft() + model.offsetX,
            getPaddingTop() + model.offsetY);

    for (int column = model.colStart; column <= model.colEnd; column++) {
        for (int row = model.rowStart; row <= model.rowEnd; row++) {
            MyHolder tile = coreService.getActiveTile(column, row);
            if (tile != null) {
                // 到这里瓦片的世界坐标是 (0,0)，尺寸是
                // coreService.getTileWidth(column) x coreService.getTileHeight(row)
                // TODO 在当前位置绘制瓦片内容
            }
            // TODO 绘制完一行后，把画布下移一行的高度，继续下一行
        }
        // TODO 绘制完一列后，把画布右移一列的宽度，继续下一列
    }
    canvas.restore();
}
```

- 列宽/行高要逐格取 `getTileWidth(column)` / `getTileHeight(row)`，因为可变尺寸下每格可能不同，不能乘固定值
- `getActiveTile(column, row)` 返回 `null` 表示稀疏格子，直接跳过
- 两处 TODO 是坐标系累加，参考 `TileView` 的 `onDraw`

> 缩放：绘制时把 `model.offsetX/offsetY` 乘上 `getScaleFactor()` 即可让瓦片跟随缩放（参考 `TileView.scale()`）；启用双指快照缩放需要注册 `ZoomInterface`，见「第七步：接入缩放」。

#### 第五步：适配器与瓦片持有者

```java
public static abstract class MyAdapter extends TileAdapter<MyHolder> {
}

public static class MyHolder extends TileCoreService.BaseTileHolder {
    // 自绘场景：持有绘制所需的数据即可，例如
    // public void draw(Canvas canvas) { /* TODO */ }
}
```

- `onCreateTileHolder` 返回 `null` 表示该格子稀疏，核心服务会跳过
- 持有者会随滚动被创建、复用、回收，不要在持有者里缓存与位置强相关的状态
- `BaseTileHolder` 自带 `getColumn()/getRow()/getWidth()/getHeight()/getType()`，绘制时直接用

#### 第六步：接适配器

```java
public void setAdapter(MyAdapter adapter) {
    if (this.adapter != adapter) {
        coreService.reset(); // 换适配器必须重置全部状态
    }
    this.adapter = adapter;
    coreService.seek(adapter.getLeftBound(), adapter.getTopBound(), 0, 0);
}
```

到这里最小自定义 View 就成型了。剩下的 `offset/seek/snap/update/尺寸修改` 都是核心服务的透传，按需暴露即可，方法清单见 API 文档。

#### 第七步：接入缩放

缩放分两层：**基础缩放**（API 调用）与**双指快照缩放**（手势）。

基础缩放免费获得：核心服务的 `zoom/zoomBy` 会更新 `scaleFactor` 并重新布局，绘制侧把偏移乘上 `getScaleFactor()`（上一步的说明）即可。

双指快照缩放需要注册 `ZoomInterface`，否则 `EventHandler` 收到第二根手指时 `beginZoom()` 返回 false，手势被忽略。`ZoomInterface` 是渲染端与核心服务的缩放契约，三个方法对应快照的生命周期：

```java
// 缩放开始时截取画面并切换到快照渲染
@Override
public boolean captureZoomSnapshot() {
    // 1. 创建 Bitmap（尺寸 = 视图尺寸）
    // 2. 把当前画面按屏幕坐标绘制进去（复用 onDraw 的逻辑，不含缩放变换）
    // 3. 设置快照标志，之后的 onDraw 只画这张位图
    return true; // 失败返回 false，本次手势不进入缩放
}

// 缩放过程中只更新快照的变换：先平移再缩放（与核心服务结算公式一致）
@Override
public void onZoomUpdate(float scale, float translateX, float translateY) {
    // onDraw 里: canvas.translate(translateX, translateY); canvas.scale(scale, scale); drawBitmap(...)
    postInvalidateOnAnimation();
}

// 缩放结束：恢复常规渲染
@Override
public void releaseZoomSnapshot() {
    // 清除快照标志，bitmap.recycle()
    postInvalidateOnAnimation();
}
```

注册：`coreService.setZoomInterface(zoomInterface)`（在创建核心服务后调用）。

> 直接复用现成实现：`widget/zoom/ZoomSnapshot` 封装了位图创建、复用与变换绘制，`TileView`/`TileLayout` 都是通过它接入的。自定义 View 照抄即可，只需实现 `ZoomSnapshot.Renderer` 的四个方法（快照宽高、绘制内容、请求重绘）。

**生命周期约定**：`TileCoreService` 负责会话状态机——`beginZoom` 失败不入会话；缩放中 `sync` 把平移累积到快照、`seek`/`setBounds`/尺寸修改会先 `cancelZoom()`（快照与画面错位的情况一律放弃）；`onDetachedFromWindow` 里务必释放快照位图（`TileView` 在 detach 时调用 `coreService.cancelZoom()`）。

#### ViewGroup 场景

如果瓦片需要是真实子 View（类似 `TileLayout`），区别只在下面几点：

- `onTileIn` 里把子 View 加入视图树，`onTileOut` 里移除：

```java
@Override
public void onTileIn(MyHolder holder, int column, int row) {
    addViewInLayout(holder.itemView, -1, holder.itemView.getLayoutParams(), false);
}

@Override
public void onTileOut(MyHolder holder, int column, int row) {
    removeViewInLayout(holder.itemView);
}
```

- `onLayout` 里遍历模型，按 `getTileWidth/getTileHeight` 摆放每个子 View：

```java
@Override
protected void onLayout(boolean changed, int l, int t, int r, int b) {
    LayoutModel model = coreService.getLayoutModel();
    // TODO 双循环遍历 colStart..colEnd / rowStart..rowEnd
    // 每个活跃瓦片：holder.itemView.layout(x, y, x + w, y + h)
    // 起始坐标 = getPaddingLeft() + model.offsetX（纵向同理）
}
```

- 触摸事件要双份送达：一份走系统分发自动给子 View，一份手动给核心服务（核心服务需要感知触摸来停止惯性滚动）：

```java
@Override
public boolean dispatchTouchEvent(MotionEvent event) {
    if (!coreService.isEmpty()) {
        coreService.handleTouchEvent(event);
    }
    return super.dispatchTouchEvent(event);
}
```

> 子 View 的测量：`TileLayout` 在绑定回调里用 `MeasureSpec.EXACTLY` 按瓦片尺寸测量，照抄它的 `onBindTileHolder` 即可。

### Compose

有两种方式，一种是**复用**核心服务与底层组件，因为Kotlin中可以调用Java。一种是完全用Kotlin重写，难度较高，这里教第一种：

先做最简单的：用 `AndroidView` 直接包一个 `TileView`，一行接入：

```kotlin
@Composable
fun Tile2DEmbedded(adapter: TileView.Adapter, modifier: Modifier = Modifier) {
    AndroidView(
        modifier = modifier,
        factory = { context -> TileView(context).apply { setAdapter(adapter) } }
    )
}
```

代价是 Compose 树里嵌了一个传统 View，测量、绘制都走 View 体系，交互上和直接用 `TileView` 没有区别。

更彻底的做法是**不经过 View**，让 `TileCoreService` 直接在 Composable 里驱动渲染。思路与自定义 View 完全一致，只是把 View 生命周期换成 Composable 生命周期：

```kotlin
@Composable
fun Tile2DComposable(modifier: Modifier = Modifier, adapter: TileAdapter<*>) {
    val context = LocalContext.current
    val coreService = remember {
        TileCoreService<ComposeTileHolder>(context, object : TileCoreService.CoreInterface<ComposeTileHolder> {
            override fun updateUI() {
                // TODO 触发 Compose 重组：维护一个 mutableStateOf 计数自增即可
            }
            // TODO 其余 CoreInterface 方法与自定义 View 完全一致，委托给 adapter
        })
    }

    DisposableEffect(Unit) {
        onDispose { coreService.resetAnimator() } // 对应 onDetachedFromWindow
    }

    // TODO Modifier.onSizeChanged：setBounds(...) + sync(0f, 0f)
    // TODO Canvas：遍历 LayoutModel 绘制瓦片，逻辑同自定义 View 的 onDraw
}
```

几个关键差异：

- `remember` 保证核心服务只创建一次；销毁清理放 `DisposableEffect` 的 `onDispose`
- `updateUI()` 里不能调 `postInvalidate`，改用手动触发的重组状态
- 滚动可以直接用 `pointerInput` + `detectDragGestures`，把拖拽位移换算成内容位移：

```kotlin
.pointerInput(Unit) {
    detectDragGestures { change, dragAmount ->
        change.consume()
        coreService.sync(-dragAmount.x, -dragAmount.y) // 与 View 手势的符号约定一致
    }
}
```

> 瓦片若要接收完整触摸事件（点击、长按），需要把 `PointerInputChange` 组装成 `MotionEvent` 再转发，工作量较大。

### OpenGL ES

通常**Vulkan**是更好的选择，但它没有官方的**Java API**，所以这里选择**OpenGL ES**，可以复用核心服务和所有底层组件。

整体结构：`GLSurfaceView` 负责承载，`Renderer` 同时实现 `CoreInterface`。核心服务跑在 UI 线程，GL 绘制跑在 GL 线程，两者之间只通过 `requestRender()` 桥接，这是整个方案的关键。

#### 第一步：GLSurfaceView

```java
public class TileGLView extends GLSurfaceView {

    private TileCoreService<GLTileHolder> coreService;

    public TileGLView(Context context) {
        super(context);
        setEGLContextClientVersion(2); // ES 2.0 起步
        // TODO setRenderer(renderer)，渲染器见下一步
    }

    @Override
    public boolean onTouchEvent(MotionEvent event) {
        if (coreService != null && !coreService.isEmpty()) {
            coreService.handleTouchEvent(event);
        }
        return super.onTouchEvent(event);
    }

    // TODO 把 onPause()/onResume() 透传给 GLSurfaceView，否则 GL 线程会崩
}
```

几个容易踩的坑：

- **坐标换算**：`getTileX(column)/getTileY(row)` 已经包含偏移与内边距，直接就是瓦片的世界坐标；像素坐标转 GL 归一化坐标需要你自己的投影矩阵
- **线程**：GL 资源只能在 GL 线程创建/释放；`onTileRecycled` 等回调发生在 UI 线程，不能直接操作 GL 对象，正确做法是先标记待释放，由 GL 线程在下一帧统一回收
- **生命周期**：`GLSurfaceView.onPause()/onResume()` 必须透传，否则 GL 线程会在后台继续跑导致崩溃
- **调试**：`DebugLayer` 依赖 `Canvas` 绘制，GL 场景不适用，需要实现数据面板

---

三种方案的共同点是：**核心服务与底层组件完全复用**，变的只有「怎么把瓦片画出来」。建议先跑通自定义 View，再迁移到 Compose / OpenGL ES，成本很低。
